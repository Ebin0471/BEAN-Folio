## 5. Contract deviations / notes

1. **Two-version compare patches** (§8 "choose two"): §4 only exposes `versions/[versionId]/diff` vs CURRENT — there is no A-vs-B patch route. Implemented honestly: Compare mode computes a path-level inventory (added/removed/size-modified) from the two `GET versions/[id]` file lists, and each row's "Diff vs current" shows the real unified patches. Nothing is fabricated; the dialog explains the distinction inline.
2. **Rollback buttons**: task wording offered two readings ("NOT the newest" vs "every LIVE row"); implemented the simpler "Rollback on every LIVE row" — the server (§7.1) rejects invalid rollbacks and errors surface honestly.
3. **Files-preview iframe placement**: rendered as DeviceStage children per §8 ("inside DeviceStage instead of the SiteRenderer children") — i.e. it lives inside the existing preview iframe shell; relative `/api/...` src resolves against the app origin (srcdoc base), sandbox `allow-scripts` propagates as specified.
4. **`files/content` GET binary**: client types mirror §4 exactly (`{ file, binary }`, no content unless the backend serves `?raw=1`; the CodeWorkspace never requests raw).
5. **Backend not present yet**: at implementation time `files/*`, `builds/*`, `versions/*`, `activity`, `deployments/*`, `domains/*` routes (and the `deployment` field on the public route) did not exist — every surface renders its honest error/empty state instead of stub data, per the API-contract note.
6. `getSiteVersion` was added to `giftz-client.ts` (not in the task's function list) because the Compare mode needs `GET versions/[versionId]` — it is part of the §4 route table.
