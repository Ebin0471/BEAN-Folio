# GIFTZ — OPEN SOURCE LICENSE REGISTER (CODE GIFTZ expansion)

**Audit date:** 2026-11-21.
**Purpose:** precise, honest license-safety register for the CODE GIFTZ website-studio expansion of BEAN Folio (private, commercial product). Every component that is vendored into generated websites, bundled into the platform app UI, planned for adoption, or studied for concepts must appear here with a verified license and an explicit integration decision. This register extends (does not replace) `docs/OPEN_SOURCE_REGISTER.md` (M0/M15–M17) and inherits its governance rules (§3: every new runtime dependency gets an entry before merging; GPL/AGPL/BSL/source-available rejected by default; re-check on every major-version bump).

## 1. Verification methods (per-row legend)

The "License (verified how)" column states the exact evidence source for each row. Methods used on this audit date:

| Tag | Meaning |
|---|---|
| `node_modules` | Read from the installed, pinned package inside this repo (`LICENSE*` file, `package.json` `license` field, and/or dist-file `@license` headers). Highest confidence — this is the actual code we ship. |
| `npm registry` | Fetched live from `https://registry.npmjs.org/<pkg>` (`license` field of the latest published version). Metadata-level verification; LICENSE file inside the tarball must be re-checked at install time. |
| `raw LICENSE` | Fetched live from `raw.githubusercontent.com/<owner>/<repo>/<branch>/LICENSE*`. The GitHub REST API (`api.github.com`) was **rate-limited (0/60 remaining)** on 2026-11-21, so raw license files were used instead of API license metadata. Repo star counts / push dates / commit SHAs were therefore **not** captured. |
| `repo doc` | Recorded in an existing repo license-review document (cited per row). Not re-verified on this audit date. |

Honesty rule: where verification was not possible, the row says **UNVERIFIED — reason** explicitly. No license claim in this register is fabricated.

## 5. Safeguards preserved

1. **Reference-only posture for restricted/reference repos** — `docs/GIFTZ_REACT_BITS_LICENSE_REVIEW.md` remains binding: no react-bits source anywhere (`origin: "original"` + `license: "GIFTZ original (no third-party source)"` pins in the component registry, test-enforced; grep-clean audit recorded). This register keeps react-bits in §2.3/§4 accordingly and extends the same discipline to all eleven concept-studied repositories: patterns studied, nothing copied.
2. **GSAP boundary preserved** — GSAP files are emitted per-project from the pinned npm package into end-user websites only (normal licensed use); GIFTZ never ships GSAP as a redistributable developer library, SDK, or catalogue (`docs/OPEN_SOURCE_REGISTER.md` §4 row stands). Optional-by-default bundling is test-pinned: sites without `motion.gsap`/`backgroundEffects` bundle zero animation bytes (`tests/giftz-motion-engine.test.ts`).
3. **Vendored files carry license evidence** — three.min.js embeds its MIT/SPDX header (verified); every GSAP dist file embeds the `@license … standard-license` header (verified). Vanta's missing embedded header is the one open attribution action item (§2.1 / §4 action list below).
4. **Register governance inherited** — every adopted dependency keeps its entry before merge (`docs/OPEN_SOURCE_REGISTER.md` §3), license re-check on every major-version bump, and rejected alternatives stay recorded. The CodeMirror rows in §2.2 become "vendored+verified" only after the install-time LICENSE re-check records the exact pins.
5. **CSP/self-hosting unchanged** — generated sites reference only self-hosted `assets/vendor/*` (no CDN, `connect-src 'none'`), so no license-uncontrolled third-party code can enter generated output (`docs/GIFTZ_MOTION_SECURITY.md`, `docs/GIFTZ_VANTA_INTEGRATION.md` §10).
