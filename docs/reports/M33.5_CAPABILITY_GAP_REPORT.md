## 4. OCR decision (recorded up front)

Spec §4.3 permits shipping scan detection + the honest unsupported message when a safe rasterization+OCR path cannot be delivered with full licence/pinned-asset review and CPU benchmarking. Decision for this milestone: **OCR explicitly deferred.** Rationale:
- `tesseract.js` (Apache-2.0) does not parse PDFs; a safe PDF rasterizer would be a new dependency requiring its own provenance review, and trained language data is a separately licensed artifact that must be pinned and audited per spec §9.2.
- The existing parse route already detects image-only PDFs and states the limitation honestly — no silent failure.
- No new dependency is required for any other M33.5 phase (pdf-parse, mammoth, docx, pdfkit, zod all already vendored), keeping the dependency/licence surface unchanged.
