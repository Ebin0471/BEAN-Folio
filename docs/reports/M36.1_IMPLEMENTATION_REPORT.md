## 5. Evidence classification rules (binding ladder, as implemented)

- **DECLARED** — profile fields (`headline`, `availability`, `location`, `experienceLevel`), `ProfileSkill` labels, declared professions, self-declared project tags.
- **DEMONSTRATED** — a real project record: for self-analysis the owner's OWN projects (every row states its ACTUAL `status`/`visibility`/`archived` state and `publiclyDiscoverable: status==='PUBLISHED' && visibility==='PUBLIC' && !archived`); for third parties ONLY PUBLISHED + PUBLIC + unarchived projects. A skill is DEMONSTRATED only when a permitted project record carries the matching skill tag.
- **VERIFIED** — ONLY real `TrustVerification` rows with `status = "VERIFIED"` (kinds PHONE / IDENTITY / PROFESSIONAL_CREDENTIALS / TALENT_PARTNER_AUTHORIZED), account-level, kind+status+reviewedAt only (never notes/evidenceReference). **No per-skill or per-project verification exists; none is synthesized** (pinned by tests). Third-party verification evidence NEVER appears in `portfolio.publicEvidence` output.
- **UNKNOWN** — insufficient evidence (e.g. a required role skill with no declaration and no project evidence); never upgraded.

Every report carries: strengths (each citing its evidence), gaps (each naming the missing evidence),
highlight recommendations, limitations, `unassessedAreas[]` (media content, external URLs, resume/cover-letter
documents, engagement metrics deliberately excluded as competence evidence) and a provenance block
(sources, method, retrieval time, consent note). No quality scores, rankings or hiring predictions.

## 6. AI_PROCESSING consent guard (New Implementation — the §10.3 gap is closed)

`resolveCurrentAiProcessingConsent(subjectUserId)` in `portfolio-tools.ts` performs, on EVERY
`portfolio.publicEvidence` execution, a FRESH read through the existing service
`getCurrentConsent(userId, "AI_PROCESSING")` (`src/lib/ox/consent.ts`) and additionally requires the
current server-owned `OX_CONSENT_VERSION`. Nothing is cached; a previous response never authorizes a
later execution.

- **No current consent** (`NO_ROW` / `REVOKED` / `EXPIRED` / `STALE_VERSION`): declared + link-level public
  output is returned (subject block, declared professions/skills, public project metadata + `/p/` links,
  focus relevance), `aiProcessingConsent: { current: false, reason }`, an explicit limitation names
  AI_PROCESSING — and **the AI gateway is never called** (proven by a recording gateway spy, not a returned flag).
- **Current consent:** a bounded AI analysis over ONLY the evidence retrieved in THIS request
  (Zod-validated `publicAiAnalysisSchema`; honest `llmError` fallback on gateway failure or contract
  violation — the deterministic output always stands on its own). AI-derived results are NEVER persisted
  or cached.
- **Self-analysis distinction:** `portfolio.evidenceReport` analyses the owner's OWN records at the
  owner's explicit request and is fully deterministic — zero gateway calls, no third-party consent
  required (pinned by tests: `AI_CALLS.length === 0`).
- **Prompt-injection safety:** the analysis system prompt marks the evidence block UNTRUSTED USER-PROVIDED
  DATA with absolute rules (no instruction-following from content, no invention, no verification claims,
  no scores, no sensitive-trait inference, no instruction disclosure). Pinned by an injection test.
- **Existing policy respected:** `User.aiConsent` gates nothing (documented in `src/lib/ai.ts`); the
  gateway's burst/daily limits are HTTP-route guards (`aiGate`) and were not bypassed — the tool layer
  calls `aiComplete` exactly as the existing specialist tools do.
