## 3. What was implemented

### 3.1 Specialist — `laxii-art-director` (PERSONAL + ORGANIZATION)

Registered over the ONE new read-only tool plus the EXISTING registered LAXII tools (`laxii.banner.brief`, `laxii.banner.produce`, `laxii.job.status`) — no duplicate pipeline, no invented tool names. `riskPolicy.maxAutomationLevel: 2` allows the role to PLAN an existing level-2 generation step, but the registry stays authoritative: `laxii.banner.produce` remains MEDIUM/level 2 with the existing explicit owner approval, image/cost guards and durable worker; `approvalsAlwaysHuman: true`. `available()` re-verifies every referenced tool in the live registry on every read. Workspace scopes are PERSONAL + ORGANIZATION; LAXII records remain USER-owned on every execution — an organization member can never inspect another member's private briefs, jobs, media or documents, and no shared-ownership model was invented.

### 3.2 The tool — `laxii.art.direction` (LOW / level 1 / read-only / idempotent / undo null / no verify hook / audit `riishe.tool.art_direction`)

Strict zod input with bounded lengths/arrays and exactly ONE source at a time:

- **A. Existing structured brief** — `briefTaskId` | `briefTaskRef` (the existing M35 typed reference; a POINTER, never authorization). Loaded through the EXISTING owner-scoped `loadBriefTask(ctx.userId, taskId)`.
- **B. Existing generation job** — `jobRef` | `messageId` (existing M35 typed reference). Read with an owner-scoped query on the OWNING conversation (`conversation: { userId: ctx.userId }`), selecting only `id/conversationId/role/operation/status/error/metaJson` — binary image data and private media paths are never read.
- **C. Explicit fresh request** — bounded `request` (1..2000) + optional bounded `toneWords`/`audience`/`purpose`. Advisory-only; no brief or task is created. Mixed sources are schema-rejected (a request may never simultaneously identify a brief and a job); `proposedRevision` requires the brief source; context fields and `brandKitContext` require the request source.

Direction proposal (brief or request path):
- `detectArtDirection()` — the EXISTING deterministic seven-direction classifier. A null classification returns an honest unresolved direction with the seven recognisable ids listed; a fabricated best match is never produced.
- Style recommendations: ONLY real `STYLE_PRESETS` slugs through an explicit documented direction→presets mapping (≤3), public metadata only (slug/label/blurb/defaultAspect/referenceBehavior) — the server-side `promptFragment` never ships; a slug absent from the live registry is filtered out rather than recommended as a ghost. No resolved direction ⇒ empty recommendations + honest limitation.
- Typography: the EXISTING `recommendBannerFontPairing()` driven ONLY by explicit values (brief path: the brief's own `visualIdentity.toneWords`/`targetAudience`; request path: the supplied context). Every recommended font id is a real provisioned family. The brief's exact user-selected typography is reported as authoritative and is never silently overridden. No glyph-coverage claims beyond what the recommender itself states.
- Palette/composition/canvas/safe-area: the brief's stored fields verbatim. An absent palette is stated honestly — hex values are never invented.
- Optional brand kit (request path): ONLY explicit schema-supported attributes passed to the EXISTING `buildBrandKitProposal()`; unknown explicit ids remain rejections surfaced through the existing `brandKitRejection()` conversion — never substitutions; actual assumptions and warnings are returned; proposals are advisory and never applied or persisted.

Job review path (honesty rules):
- RUNNING → no completed quality verdict (explicit reason; findings never invented).
- FAILED → the actual recorded error is reported; no quality findings exist.
- DONE + stored `qualityReport` → structurally validated (overall/evaluator/evaluatedAt/findings/aiReview shapes and bounds) and returned verbatim with actual finding ids/statuses, the EXISTING `refinementDirectives()` mapping over the validated report, the evaluator provenance note, and AI-review findings kept EXPLICITLY advisory (the report's own advisory note is preserved).
- DONE without a readable report → "quality evidence is unavailable", never a pass.
- Malformed metadata/report → refused to infer; the report is never guessed at.
- Raw `metaJson`, provider internals (`interactionIds`/`estimatedCostUsd`/`outputMediaIds`/`inputAssetIds`), and binary image data are never returned. The worker's quality evaluation and persistence are untouched; the provider is never called and the worker is never restarted.

Optional revision preview (brief path, explicit `proposedRevision`):
- Compiled IN MEMORY with the EXISTING `appendRevision()` + `compileRevisionAddenda()`; only existing schema revision areas; instruction bounded by the existing 600-char schema; the existing three-revision maximum is honoured (a fourth revision honestly refused with the limit reason); the compiled addendum is scoped to the named area (everything outside stays approved); clearly labelled PREVIEW with an explicit "saving remains an explicit action in the existing LAXII workflow" note. The write path `reviseBriefTask()` is NEVER called — no AgentTask, no resultJson, no status change, no database row of any kind.

### 3.3 Routing (deterministic, conservative)

One planner block, ordered after the M36.6 GIFTZ quality clause and before the M35 creative clauses:
- Direction/style/typography language (`art direction`, `visual direction`, `style preset`, `typography recommendation`, `font pairing`, …) → `laxii.art.direction` with the clause text as the bounded explicit request (nothing invented).
- Review/feedback language (`review my banner`, `banner feedback`, `banner quality`, …) → a step ONLY with an explicit `job/message/generation <id>` or `brief <briefTask id>` identifier; review language without a target produces NO step (never the newest record, never an invented id).
- Specialist routing keywords avoid the broad `banner` keyword: banner production and cross-studio chains stay with Creative Producer; quality-audit language stays with the GIFTZ Quality Auditor; career/resume language stays with the Career Guide (all pinned by tests).

## 4. Ownership, privacy and honesty guarantees (test-pinned)

- Briefs load through the EXISTING owner-scoped `loadBriefTask`; jobs read through the owning conversation. Foreign-owned, missing, deleted and unparseable records all receive the SAME generic refusal (`"No accessible LAXII record exists for this request — nothing was analyzed."`) — existence-hiding, no leak of the foreign record's content or existence.
- ORGANIZATION workspace context never widens ownership (pinned with two members in the same org shape).
- `briefTaskRef`/`jobRef` remain typed pointers, resolved by the M35.7 engine rules (dependency-failed/missing-result honesty) and re-authorized at consumption with `ctx.userId`.
- Every recommendation identifies its basis (explicit brief data / actual registry match / stored quality evidence / honest limitation).
- No palette values, font ids, style ids, dimensions or quality measurements are ever invented.
