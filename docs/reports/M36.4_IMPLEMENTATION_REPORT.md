## 5. Implementation details

### 5.1 `ox.invitation.prepare` (LOW / Level 1 / outreach / persistent private DRAFT only)

- **Input (strict):** `{ opportunityId | opportunityRef, candidateUserId | matchRef, offer?, personalNote? (≤500), interviewFocusHints? (≤6×≤200) }` — exactly one locator, exactly one candidate source. The offer reuses `invitationOfferSchema` verbatim and is deliberately OPTIONAL at the schema level so missing terms produce the honest `NEEDS_CLARIFICATION` outcome rather than an opaque validation error.
- **Authorization (fresh per execution):** ORGANIZATION workspace hint → `requireOrgRole` OWNER/ADMIN/RECRUITER → org exists, non-SUSPENDED, VERIFIED (the invitation employer policy) → tenant-bound opportunity (`findFirst({id, organizationId})`) → status PUBLISHED (the send path rechecks the same gate) → candidate source resolved through the EXACT `assertSendGates()` source-of-selection rule (eligible + unexpired TalentMatch, else ACTIVE CandidateShortlist) → FRESH `assertCandidateDiscoverableToOrg` with `getOrgActiveMemberUserIds` (generic refusal only — never reveals consent/visibility/block reasons).
- **`matchRef` binding (M36.3 hardening):** the resolved match row is re-read; `match.opportunityId` must equal the opportunity being prepared (which is itself bound to the workspace organization) — a workflow in organization A can never use a match from organization B merely because the owner holds a membership in B (proved by a dedicated test). A stale/ineligible referenced match refuses honestly.
- **Creation:** ONLY `createInvitationDraft()` — duplicate one-active check, transactional creation, database P2002 uniqueness backstop, `ox.invitation.drafted` audit inside its transaction (no duplicate OX draft event fabricated by the tool; the registry declares its own `riishe.tool.ox_invitation_prepare`). `InvitationRuleError` codes are mapped onto honest outcomes (`DUPLICATE_INVITATION`, `INVALID_OFFER`, `REFUSED`).
- **Never:** `sendInvitationDraft`, `createAndSendInvitation`, `notifyCandidateOf`, any send route. Verified by source pins AND runtime assertions (no `sentAt`, no SENT/VIEWED/NEGOTIATION_REQUESTED rows across all suite organizations, zero candidate notifications, `expiresAt` null — the response window is stamped at send).
- **Ephemeral context:** `personalNote`/`interviewFocusHints` return `stored: false`; the persisted row JSON provably contains neither (asserted).
- **Verify hook:** re-reads the row — tenant org + opportunity + candidate, status DRAFT, `createdByUserId === actor`, `sentAt` null; foreign or non-DRAFT results fail verification (tested, including a deliberately-SENT row that fails and is restored).
- **Retry honesty:** `idempotent: false`, `maxAttempts: 1` — no idempotency field exists on the model; re-running after a partial failure surfaces the duplicate refusal instead of claiming exactly-once. Undo = discard the draft in the employer UI.

### 5.2 `ox.interview.prepare` (LOW / Level 1 / relationship / private artifact only)

- **Input (strict):** `{ opportunityId | opportunityRef | roomId, role? (≤80), stage? (enum HIRING_STAGES), focusAreas? (≤6×≤120), preparationContext? (≤500) }` — exactly one locator.
- **Authorization:** ORGANIZATION workspace required. Room-less preparation runs the employer-role trio (`requireOrgRole` OWNER/ADMIN/RECRUITER) — the same gate as the other org Opportunity Exchange tools. A supplied room is a POINTER: re-read, workspace-bound (`room.organizationId === workspace org`), resolved through the EXISTING `resolveRoomParty` — EMPLOYER_ROLES or an actively ASSIGNED HIRING_MANAGER permitted; VIEWER, the candidate, an unassigned HIRING_MANAGER and outsiders denied; a supplied opportunity that contradicts the room's opportunity is refused (`CONTEXT_MISMATCH`).
- **Preparation output:** deterministic question pack (required-skill coverage group, preferred-skill depth, per-focus probes ≤6, role/logistics group), stage purpose from the EXISTING `HIRING_STAGES` vocabulary, plan outline, evaluation dimensions stated as advisory discussion topics (never scores), customization notes, honest limitations, provenance.
- **AI layer:** ONE gateway call carrying ONLY organization-owned data (title/status, stage, skill labels, recruiter role label, focus areas, preparation context) wrapped as untrusted content with an absolute advisory contract (no invented qualifications/candidate facts, no protected characteristics, no scoring, no accept/reject). Strict output schema; invalid output rejected (deterministic pack stands); gateway failure degrades honestly. **NO candidate-specific data is ever retrieved or sent** — no candidate profile, evidence, match or interview-response data enters the gateway under ANY consent state (asserted by scanning every recorded gateway call for candidate identifiers/profile fields/match data across all AI_PROCESSING consent states, including rooms with candidates attached). AI_PROCESSING consent is never needed here and never consumed; it is never treated as a substitute either (the M36.1 resolver remains the only candidate-scope AI consent path).
- **Zero mutations:** no Interview row (count asserted before/after), no room lifecycle write (`updatedAt`/`status`/`currentStage` asserted unchanged), no meeting link generated, no notifications; `proposeInterview`/`confirmInterview`/`alternateInterview`/`rescheduleInterview`/`cancelInterview`/`completeInterview` never called (source pin asserted).

### 5.3 `ox.room.brief` (LOW / Level 1 / relationship / read-only)

- **Input (strict):** `{ roomId | invitationRef }` — exactly one locator.
- **invitationRef consumption:** the engine resolves the pointer with M35.7 rules + `verifyInvitationRefAuthorization`; the tool then RE-READS the invitation row (pointer ≠ permission), binds it to the current workspace organization, and requires the invitation's hiring room to exist (rooms are created only by the existing authorized human flow after a human ACCEPTED the invitation — no room ⇒ honest `NO_ROOM_FOR_INVITATION`; a DRAFT pointer never becomes authority for anything beyond that refusal).
- **Audience matrix (fresh per execution):** `resolveRoomParty` — EMPLOYER_ROLES (OWNER/ADMIN/RECRUITER) or ASSIGNED_MANAGER receive the brief; VIEWER / the room's candidate / an unassigned HIRING_MANAGER / every outsider get an existence-hiding denial. Room bound to the workspace organization. Organization VERIFIED + non-SUSPENDED enforced per the employer room policy (`requireRoomEmployerAccess` convention). The EXISTING `ox:room-read` rate-limit bucket (120/hour/user) is reused — the SAME key the human room routes use, no new quota path (exhaustion test: the 121st brief returns the honest shared-quota refusal).
- **Output (real rows only):** audience-appropriate room card via the EXISTING `serializeRoomForEmployer` (compensation snapshot + members + interviews with meeting links only on live PROPOSED/CONFIRMED interviews for callers holding room mutation rights — exact existing allowlist); the audit-derived activity timeline (`getRoomActivityTimeline`); stage/interview/interaction summaries computed from the real rows; requirements overview from the room's organization-owned opportunity with the honest no-response-records statement; limitations + unassessed areas + provenance.
- **Private-note rule:** `HiringStageEvent.note` CONTENT is included ONLY in the EMPLOYER_ROLES branch. ASSIGNED_MANAGER receives the same serializer output with note keys REMOVED (narrowed, never broadened) — asserted by deep string scan.
- **Zero writes:** room/stage/interview row counts and `updatedAt` asserted unchanged; no OX audit fabricated for the read (read-route parity); no lifecycle change of any kind.

### 5.4 Typed `invitationRef`

- `REF_FIELDS` += `invitationRef`, `REF_RESULT_KEYS.invitationRef = "invitationId"`; producer `ox.invitation.prepare` (emits `invitationId` ONLY on draft-creation success); consumer `ox.room.brief`; M35.7 plan-time rules unchanged (no self/forward refs, explicit dependency declaration, SUCCEEDED source, honest missing-result failure — all re-tested for the new key).
- Resolution-time enforcement (`resolveStepParams` additive branch → `verifyInvitationRefAuthorization`): row exists → tenant org from the ROW (never a client/model id) → ACTIVE OWNER/ADMIN/RECRUITER membership of the WORKFLOW OWNER in THAT org → org VERIFIED + non-SUSPENDED. Failures throw `WorkflowError(…, "authorization-revoked")` — role loss, suspension, unverification and row deletion between producer and consumer all fail the resolution (each tested). The verifier is read-only (audit-count asserted unchanged).
- Status fitness stays consumer-side (the same split convention as `matchRef`): the consumer checks the invitation's room existence; no M36.4 tool accepts an invitation reference for any sending purpose (schema-level test: no `ox.*send` tool exists; strict schemas reject `status` inputs).
- `opportunityRef` (M36.2) and `matchRef` (M36.3) continue to resolve under the existing rules (re-tested; `verifyMatchRefAuthorization` cascade re-asserted).
