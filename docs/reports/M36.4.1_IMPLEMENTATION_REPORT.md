## 3. The original authorization gap

`interviewPrepareExecute()`'s `input.roomId` branch performed:

1. `resolveRoomParty(input.roomId, ctx.userId)` — proves room existence, ACTIVE org membership, role and assignment;
2. workspace-to-room organization binding (`party.room.organizationId !== workspace.organizationId` → refuse);
3. audience check (`EMPLOYER_ROLES` / `ASSIGNED_MANAGER` only);
4. opportunity read + deterministic pack + `aiComplete()`.

`resolveRoomParty()` (`src/lib/ox/room.ts`) verifies membership and assignment only — it never consults `EmployerOrganization.verificationStatus`. Consequently the room-backed path returned `INTERVIEW_PREPARED` for rooms in PENDING-verification or SUSPENDED organizations, while:

- the room-less path (`authorizeOrgWorkspace()`) refuses missing / SUSPENDED / non-VERIFIED organizations;
- `ox.room.brief` re-reads the organization after party resolution and refuses the same states;
- the employer room routes enforce the same stack (`requireRoomEmployerAccess()`).

The gap is real, not theoretical: running the new tests against the untouched baseline proved all four refused cases returned `INTERVIEW_PREPARED` before the correction (§5, red-at-base).

## 4. The correction and its placement

Inside the `if (input.roomId)` branch of `interviewPrepareExecute()`, immediately after the role check and BEFORE `roomStage`/`roomId` assignment, the opportunity read, the deterministic pack and any `aiComplete()` call:

1. the organization is re-read fresh via the existing `getOrg(party.room.organizationId)` — the authoritative organization ID **from the room**, after the workspace binding has been confirmed (at that point equal to the workspace organization, but the room's value is used as the authoritative pointer);
2. missing organization → honest `UNAUTHORIZED` (existence-hiding, generic reason);
3. `verificationStatus === "SUSPENDED"` → `UNAUTHORIZED` ("This organization is suspended — hiring-room access is unavailable.");
4. `!orgIsVerified(roomOrg)` (the existing convention) → `UNAUTHORIZED` ("Employer verification is required for hiring-room access — verify the organization in the Opportunity Exchange first.");

Gate-order parity: the module's own conventions place the audience decision before the organization-state check (`authorizeOrgWorkspace`: role → org → SUSPENDED → VERIFIED; `requireRoomEmployerAccess`: membership/role → org → SUSPENDED → VERIFIED; `roomBriefExecute`: party → access → binding → org state). The inserted gate follows exactly that order, keeping all authorization gates together before any data read.

Invariants preserved:

- `ctx.workspace.membershipRole` remains untrusted; `resolveRoomParty()` remains the sole audience authority for `EMPLOYER_ROLES` and the actively assigned HIRING_MANAGER (the new gate applies identically to both — assignment never bypasses organization standing);
- the room-less authorization path is unchanged;
- refusals disclose no private room, organization or candidate data (no ids, names, statuses, compensation, notes);
- the operation remains private, prepare-only and mutation-free.
