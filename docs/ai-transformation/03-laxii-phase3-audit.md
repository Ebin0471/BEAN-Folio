# Phase 3 audit — LAXII Creative Intelligence (repository-first, read-only)

Scope of this audit: everything Phase 3 touches — LAXII providers/routing, banner pipeline and
`fitToCanvas`, the 942×190 preset, version lineage, media storage/upload, the Riishe design-brief
handoff, AgentTask/approval, the intelligence gateway/cost ledger/capability registry, and tests.
Written before any Phase 3 code. Facts below carry file:line anchors so later phases can re-verify.

## 1. What already works (reuse — do not duplicate)

### LAXII engine core (`src/lib/laxii/`)
- **Provider architecture** (`router.ts`): 4-provider registry — `managed` (z-ai gateway, always
  available server-side), `gemini`, `openai`, `diffusers` (each available only with credentials;
  unconfigured providers are refused, never silently substituted — `resolveProvider` router.ts:70-87).
  Every operation runs capability check → real provider call → `validateGeneratedImage` →
  deterministic post-processing (aspect center-crop, transparency extraction) router.ts:219-253.
  Per-image cost estimates (`estimateUnitCost` router.ts:101-113), duration measurement, and
  gateway health reporting (`recordProviderSuccess/Failure`, router.ts:203-215) are wired.
- **Output validation** (`validate.ts`): magic-byte probing (`probeImage`), min-edge, truncation and
  GIF rejection; `pngHasAlpha` for true-transparency detection.
- **Deterministic pixel ops** (`image-ops.ts`): `cropToAspect` (center crop, no stretch),
  `composeReferenceSheet` (multi-reference → single contact sheet for managed), `prepareExpandCanvas`
  (outpainting prep), `extractTransparency` (flood-fill alpha, coverage sanity), and **`fitToCanvas`**
  (cover-fit + center crop to EXACT pixel dimensions, PNG/JPEG/WebP, image-ops.ts:207-223).
- **Banner preset** (`banner-presets.ts`): single authoritative `bean-folio-banner` preset —
  **942×190**, safeArea = centered 86%×90% (≈810×171), `compositionHint` telling the model to keep
  everything in the vertical center band. `findBannerPreset` + `resolveBannerCanvas` enforce it.
- **Async job runner** (`jobs.ts`): POST /api/laxii/generate only CREATES a turn (202 + RUNNING
  LaxiiMessage); the engine runs in-process afterwards. Honest states only (DONE only after versions
  exist; FAILED with safe message otherwise). Idempotency: duplicate generate while RUNNING returns
  the same job (generate/route.ts:291-305); retried versions skip already-persisted mediaIds
  (jobs.ts:190-194); stale RUNNING jobs swept to FAILED after 30 min (`sweepStaleLaxiiJobs`).
- **Version lineage** (`schema.prisma` LaxiiImageVersion:447-468): `parentVersionId` tree,
  `isSelected` (exactly one per conversation, enforced in select route transaction),
  `isFavourite`. Select/undo/redo = re-selecting ancestors/descendants.
- **Storage boundary** (`service.ts`): generated bytes stored as ordinary owner-scoped MediaAssets;
  served only via `/api/media/[id]/raw`; references loaded with ownership checks
  (`loadOwnedMediaAsReferences`).
- **Conversational intelligence** (`intent.ts`): AUTO intent classification (LLM-first with
  deterministic rule fallback), preservation-directed edit compilation, conversation-context brief.
- **Styles** (`styles.ts`): 14 style presets compiled server-side; avatar presets similarly.

### Banner generation + export (existing working pipeline)
- `POST /api/laxii/generate` with `operation:"BANNER"` + `banner.presetSlug` builds
  `promptFinal = prompt + canvas note + compositionHint`, resolves `nearestAspect(4.958)` = 21:9,
  sets `bannerCanvas {942,190}`, and the job composites every output onto the EXACT canvas with
  `fitToCanvas` (jobs.ts:166-177). Verified in Phase 2 E2E: output exactly 942×190 in DB.
- `POST /api/laxii/banner/export` re-encodes to the conversation canvas, **verifies by decode**
  (`probeImage` width/height match) and only then stores the derived asset (route lines 59-66).

### Riishe → LAXII handoff (Phase 2b, to be deepened)
- `delegation.ts` `detectDelegationIntent` (conservative regex + negations) and `prepareDelegation`
  build a portfolio-grounded **natural-language** brief from `buildPortfolioContext` (own data only),
  persist a durable **AgentTask** (`status:"AWAITING_APPROVAL"`, steps+result JSON) and return a
  delegation payload to the RIISHE chat UI.
- `IntelligenceView` renders the brief card; the handoff button copies the brief to the clipboard and
  navigates to `#/laxii`. **LAXII never receives the brief structurally** — see gaps.

### BEAN Intelligence gateway (Phase 1)
- `gateway.ts`: gatewayComplete/gatewayStream/gatewayVision (vision accepts ≤5 data-URL images —
  usable for AI visual review), same-capability-only transient fallback, structured JSON logs without
  prompts/secrets. `registry.ts`: honest capability registry (embedding deliberately empty);
  image capability bridges the LAXII registry with LAXII-family labels. `circuit.ts`: per-provider
  breaker + transient-only retries (1.5s/4s, ≤3 attempts).
- **Cost ledger**: `LaxiiUsage.costEstimateCents` per generation; `POST /api/laxii/generate` refuses
  new jobs when today's estimate sum ≥ `INTELLIGENCE_DAILY_COST_LIMIT_USD` (default $5.00)
  (generate/route.ts:98-112); separate 80/day + 6/min volume guards.

### UI/UX (`LaxiiStudio.tsx` + `LaxiiBannerPanel.tsx`)
- Studio: conversation sidebar (kinds IMAGE/BANNER/AVATAR/RESUME), composer, job polling
  (2.5 s interval, 7-min deadline, re-attach on mount), version thumbnails with selected ring,
  compare (parent vs selected), undo/redo through the version tree, lightbox, gallery tabs,
  warnings/intent chips per message, banner panel with true-ratio canvas + safe-area overlay +
  validated export. Mobile layout verified in Phase 2 E2E.

## 2. What is missing (the Phase 3 gap list)

1. **Structured brief ingestion** — the AgentTask brief is one natural-language blob in `resultJson`;
   no schema, no API to read it back, no LAXII consumption. The handoff button persists nothing
   (hash router strips query strings); LaxiiStudio reads no storage/params.
2. **No AgentTask lifecycle API** — no read/approve/reject/revision endpoint; AWAITING_APPROVAL is
   written once and never transitions; no stale-RUNNING sweep for AgentTasks.
3. **No professional banner composition pipeline** — current banner flow is single-pass
   generate → cover-crop. No subject-placement plan, no deterministic typography layer, no
   safe-area enforcement beyond the prompt hint, no composite step, no attempt loop.
4. **No quality-evaluation engine** — only pre-storage validation (validate.ts). Nothing measures
   sharpness/contrast/letterboxing/border coherence; nothing checks exact output size vs requirement,
   unintended transparency, text clipping/contrast/overlap, or requirement compliance vs the brief;
   no honest compliance report (satisfied / not satisfied / unsupported / needs-approval).
5. **No bounded refinement** — no re-evaluation loop, no best-of selection, no defect-aware prompt
   refinement; also no per-attempt artifact trail (legacy `tempstore.ts` + `data/laxii-tmp` exist but
   are dead code since the engine refactor; the MODNet segmentation pipeline described in
   `docs/laxii/README.md` was removed in the refactor — only ONNX weights remain on disk).
6. **No quality/refinement UI** — findings, attempts, approval (approve/reject), targeted revision.
7. **Realism capability wiring** — reference-guided generation exists (managed ≤3 refs, gemini ≤10,
   openai edit ≤16; sizes 2016×864 managed, 1K/2K/4K gemini) but is undocumented as a banner
   capability and unused by the banner flow; no evaluation of facial-identity-preservation /
   inpainting / hi-res export paths (Phase 3 delivers an honest capability note, no invented models).
8. **Tests** — no LAXII banner/brief/quality tests exist (gateway/delegation tests cover intent only).

## 3. Constraints honored by the existing design (keep)

- No rebuild: everything above is additive on top of `router.ts`/`jobs.ts`.
- No Ollama, no fabricated model ids, no fake success states, unconfigured providers stay disabled.
- 942×190 pipeline is working — Phase 3 must preserve its contracts (same preset slug, same export
  verification) and only add the structured-brief path alongside the free-form path.
- Branding: user-facing labels stay LAXII-family; provider internals only in server logs.
- Cost/volume guards and ownership checks already live in the generate route; new paths must reuse them.
