# BEAN Folio — Standardize Banner Dimensions & Fix Image Upload Failures

## 1. Standard Banner Specification

Use the uploaded reference banner dimensions as the standard:

- Width: 2048 px
- Height: 687 px
- Aspect ratio: 2.981:1 (approximately 3:1)
- Display ratio: `2048 / 687`

Apply this consistently to all banner/cover-image areas wherever applicable:

- User profile cover/banner
- LAXII banner/cover sections
- Portfolio presentation and public profile banner
- Other existing banner upload and display components that share this functionality

Do not apply this ratio to avatars, profile pictures, thumbnails, or ordinary content images.

## 2. Image Display Requirements

- Maintain the 2048:687 aspect ratio.
- Use responsive width: 100%.
- Use `object-fit: cover` for banner presentation.
- Use centered positioning by default, with existing focal-point adjustment functionality preserved.
- Avoid stretching, distortion, unexpected cropping, and layout overflow.
- Keep the banner height proportional to its width.
- Ensure desktop, tablet, and mobile layouts remain responsive.
- Update upload previews and crop/adjust interfaces to use the same ratio.
- Preserve existing user-uploaded banners and their saved focal positions wherever possible.

## 3. Fix Avatar and Banner Upload Failures (HTTP 405)

The current profile page shows `Upload failed (405)` for both avatar and cover uploads.

Investigate the actual root cause before modifying anything.

Inspect:
- Frontend upload request method and URL.
- Backend API route definitions and allowed HTTP methods.
- Next.js route handlers, middleware and proxy configuration.
- Authentication and CSRF requirements.
- Storage provider integration and upload adapter.
- Presigned upload flow, if applicable.
- Content-Type, multipart/form-data and request body handling.

HTTP 405 means the request method is not allowed by the responding route. Do not treat it as a file-size error without evidence.

Identify whether the failure occurs during:
1. Upload URL creation.
2. Direct file upload to storage.
3. Finalization or database update.

Fix the actual failing stage. Preserve the existing storage architecture and security controls.

- Existing image replacement works.

Add regression tests for the upload routes and banner-ratio behavior.
