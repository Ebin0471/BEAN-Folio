    41→## CONVENTIONS (all agents MUST follow)
    42→
    43→### Next.js 16 specifics
    44→- Route handler dynamic params are Promises: `export async function GET(req: NextRequest, { params }: { params: Promise<{ id: string }> })` → `const { id } = await params`
    45→- `cookies()` from `next/headers` is async: `const store = await cookies()`
    46→- Use `NextRequest`/`NextResponse` from `next/server`
    47→- All API routes under `src/app/api/**/route.ts` (API routes are allowed; PAGE routes other than `/` are NOT)
    48→
    49→### Server helpers (already implemented by orchestrator — import, do not re-create)
    50→```ts
    51→import { db } from '@/lib/db'                    // Prisma client
    52→import { getSessionUser } from '@/lib/auth'      // → User | null (validates session cookie)
    53→import { setSessionCookie, clearSessionCookie } from '@/lib/auth'
    54→import { ok, err, parseBody, getClientKey, rateLimit } from '@/lib/api-helpers'
    55→import { saveUpload } from '@/lib/media'         // validates magic bytes, writes to uploads/
    56→import { aiComplete, aiCapabilities } from '@/lib/ai'
    57→```
    58→- `ok(data, status=200)` → NextResponse.json(data)
    59→- `err(message, status=400, code?)` → NextResponse.json({ error, code? }, { status })
    60→- `parseBody(req, zodSchema)` → `{ data } | { response }` — check `if ('response' in r) return r.response`
    61→- `rateLimit(key, limit, windowMs)` → boolean (in-memory)
    62→- Hash passwords with `hashPassword` / `verifyPassword` from `@/lib/auth` (scrypt, never store plaintext)
    63→
    64→### Error shape (all endpoints)
    65→- 400 validation `{ error: string }`, 401 `{ error: 'Authentication required' }`,
    66→  403 `{ error: 'Not allowed' }`, 404 `{ error: 'Not found' }`, 429 `{ error: 'Too many requests' }`, 500 `{ error: 'Something went wrong' }`
    67→- NEVER leak stack traces, internal errors, or secrets. Wrap handlers in try/catch → err('Something went wrong', 500)
    68→
    69→### Visibility rules (server-enforced, everywhere)
    70→- Project PUBLIC: readable by anyone; UNLISTED: readable by direct id but excluded from feeds/search; PRIVATE: owner only
    71→- Auth-required endpoints: 401 without session
    72→- Blocked users: neither party can follow/inquire/see each other in feeds (filter by Block in both directions)
    73→- Soft-deleted users (`deletedAt != null`): treated as not found on public endpoints
    74→
    75→### Frontend conventions
    76→- ONLY hash routing via `src/lib/hash-router.ts` (`navigate(to)`, `useHashRoute()`)
    77→- Fetch via `src/lib/client.ts` `api<T>(path, init?)` — it throws `ApiError` with `.message` and `.status`
    78→- Session via `useSession()` from `src/lib/session.tsx` → `{ user, loading, refresh, logout }`
    79→- Brand: dark obsidian premium editorial. Gold `--primary` (#E8BC51) accent. NO blue/indigo
    80→- Use existing shadcn/ui components (`@/components/ui/*`) + shared atoms in `@/components/bean/*`
    81→- Cards: `p-4`/`p-6`, `gap-4`/`gap-6`, consistent `rounded-xl`. Long lists: `max-h-96 overflow-y-auto`
    82→- Every async view: loading skeleton, empty state (`EmptyState`), error state, success toast (sonner)
    83→- Responsive: mobile-first, `sm:/md:/lg:` prefixes. Footer must stick to bottom (handled in shell)
    84→- `MediaUrl` format: `/api/media/{mediaId}/raw` — use directly as img/video src
    85→
    86→### Demo fixtures vs real data
    87→- `User.isDemo = true` marks seeded fixture accounts. Seed script: `scripts/seed.ts` (explicit `bun run scripts/seed.ts`)
    88→- Never fabricate AI output, stats, or integration success states in product code

    92→## API CONTRACT v1 (authoritative)
    93→
    94→All endpoints under `/api`. JSON bodies. Cookie session auth (`bean_session`).
    95→
    96→### Auth
    97→- `POST /api/auth/register` `{ email, password (min 8), name }` → 200 `{ user: PublicMe }` + sets cookie. 409 if email taken.
    98→- `POST /api/auth/login` `{ email, password }` → 200 `{ user: PublicMe }`. 401 invalid credentials.
    99→- `POST /api/auth/logout` → 200 `{ ok: true }`, clears cookie.
   100→- `GET /api/auth/me` → 200 `{ user: PublicMe | null }`.
   101→  - `PublicMe = { id, email, name, username, headline, bio, location, avatarUrl, coverUrl, availability, contactEmail, websiteUrl, professions: string[] (slugs), skills: string[] (slugs), aiConsent, onboarded, profileVisibility, isDemo, createdAt }`
   102→
   103→### Onboarding & profile
   104→- `POST /api/me/onboarding` `{ username, displayName, professions: string[], skills?: string[], bio?, location?, headline? }` → 200 `{ user: PublicMe }`. Validates username `[a-z0-9-]{3,24}` unique. Sets `onboarded=true`.
   105→- `GET /api/me/profile` → `{ user: PublicMe, stats: { projects, published, followers, following, profileViews } }`
   106→- `PATCH /api/me/profile` (partial: `name, headline, bio, location, availability, contactEmail, websiteUrl, avatarMediaId, coverMediaId, professions, skills, profileVisibility`) → `{ user: PublicMe }`
   107→- `GET /api/profiles/:username` → public profile `{ profile: { id, name, username, headline, bio, location, avatarUrl, coverUrl, availability, websiteUrl, professions, skills, createdAt, stats: { followers, following, projects, profileViews? } }, isFollowing: boolean, projects: ProjectCard[] (public+published only; include UNLISTED if owner), collections: [{id,name,description,items:ProjectCard[]}] }`. Records a ProfileView (deduped/day).
   108→- `GET /api/professions` → `{ professions: [{ slug, label, group }] }` (curated static list served from DB seed or code constant)
   109→- `GET /api/skills` → `{ skills: [{ slug, label }] }`
   110→
   111→### Media
   112→- `POST /api/media/upload` multipart form: `file` (+ optional `kind`). → 200 `{ media: { id, kind, mime, size, url } }`. Auth required. Limits: images ≤ 8MB (jpeg/png/webp/gif), video ≤ 64MB (mp4/webm/quicktime), audio ≤ 20MB, docs(pdf) ≤ 10MB. Magic-byte validation.
   113→- `GET /api/media/:id/raw` → binary stream with content-type + cache-control. Public if linked to published content or owned; simplest correct rule: any READY media is servable (IDs are unguessable cuids) — but PRIVATE-project media must 403 unless owner: check `ProjectMedia→Project.visibility` and avatar/cover ownership.
   114→- `GET /api/media/:id` → `{ media }` metadata (owner only). `DELETE` → owner only, removes file + row.
   115→
   116→### Projects
   117→- `POST /api/projects` `{ title, summary?, description?, category?, visibility?, coverMediaId?, brief?, process?, challenges?, outcome?, role?, externalUrl?, repoUrl?, skills?: string[], tools?: string[], media?: [{ mediaId, caption? }], contributors?: [{ name, role?, contribution? }] }` → `{ project: FullProject }` (status DRAFT).
   118→- `GET /api/projects?status=DRAFT|PUBLISHED` → `{ projects: ProjectCard[] }` (OWN projects only, all visibilities).
   119→- `GET /api/projects/:id` → `{ project: FullProject, owner: PublicPerson, isOwner, isSaved, canEdit }`.
   120→  - PRIVATE → 404 unless owner. UNLISTED → readable by direct link. Records ProjectView (deduped per viewer/day) when PUBLISHED and not owner.
   121→- `PATCH /api/projects/:id` (same fields as POST, partial; owner only) → `{ project }`
   122→- `DELETE /api/projects/:id` → `{ ok: true }` (owner only)
   123→- `POST /api/projects/:id/publish` → `{ project }` (requires title + cover OR ≥1 media; sets status PUBLISHED, publishedAt). Also `POST /api/projects/:id/unpublish` → back to DRAFT.
   124→- `FullProject = ProjectCard fields + description, brief, process, challenges, outcome, role, externalUrl, repoUrl, skills: string[], tools: string[], media: [{ id, mediaId, url, kind, caption, order }], contributors: [{ id, name, role, contribution }], counts, visibility, status, publishedAt, createdAt, updatedAt`
   125→- `ProjectCard = { id, title, summary, category, coverUrl, visibility, status, publishedAt, updatedAt, owner: { username, name, avatarUrl }, counts: { views, saves }, skills: string[] }`
   126→- `POST /api/projects/:id/view` → records view (used by client on mount for anon tracking), 200 `{ ok: true }`
   127→
   128→### Discover & search
   129→- `GET /api/discover?cursor=&limit=12&category=` → `{ items: [{ project: ProjectCard, reason?: string }], nextCursor }`. Ranking: published+PUBLIC only, recency-weighted engagement (saves+views), same-profession boost for signed-in viewer, new-creator boost (first project), never follower-count-only. `reason` examples: "New on BEAN Folio", "Matches your profession: Film", "Popular in Architecture".
   130→- `GET /api/search/projects?q=&category=&skill=&sort=recent|saved&cursor=` → `{ items: ProjectCard[], nextCursor }` (PUBLIC+PUBLISHED only)
   131→- `GET /api/search/profiles?q=&profession=&skill=&cursor=` → `{ items: PublicPerson[], nextCursor }` (PUBLIC profiles only)
   132→  - `PublicPerson = { username, name, headline, avatarUrl, location, professions, skills, stats: { followers, projects } }`
   133→
   134→### Saves & collections
   135→- `POST /api/projects/:id/save` / `DELETE /api/projects/:id/save` → `{ saved: boolean }` (auth; creates notification for owner)
   136→- `GET /api/me/saves` → `{ projects: ProjectCard[] }`
   137→- `GET /api/me/collections` → `{ collections: [{ id, name, description, isPublic, items: ProjectCard[] }] }`
   138→- `POST /api/me/collections` `{ name, description?, isPublic? }` → `{ collection }`
   139→- `PATCH /api/collections/:id` / `DELETE /api/collections/:id` → owner only
   140→- `POST /api/collections/:id/items` `{ projectId }` / `DELETE /api/collections/:id/items?projectId=` → `{ ok: true }`
   141→
   142→### Follows & social graph
   143→- `POST /api/profiles/:username/follow` / `DELETE ...` → `{ following: boolean }` (auth; no self-follow; block-aware; notification)
   144→- `GET /api/me/following` / `GET /api/me/followers` → `{ people: PublicPerson[] }`
   145→
   146→### Inquiries & notifications
   147→- `POST /api/inquiries` `{ recipientUsername | projectId, type: INQUIRY|COLLABORATION|INVITE, subject, message }` → `{ inquiry }` (auth; blocked → 403; rate-limited 10/hour; notification)
   148→- `GET /api/me/inquiries` → `{ incoming: InquiryDTO[], outgoing: InquiryDTO[] }` (`InquiryDTO = { id, type, subject, message, status, createdAt, project?: { id, title }, counterparty: PublicPerson }`)
   149→- `PATCH /api/inquiries/:id` `{ status: ACCEPTED|DECLINED }` → recipient only → `{ inquiry }` (notification to sender)
   150→- `GET /api/me/notifications` → `{ notifications: [{ id, type, payload (parsed object: e.g. { actor, projectTitle }), readAt, createdAt }], unreadCount }`
   151→- `POST /api/me/notifications/read` `{ ids?: string[] }` (omit = all) → `{ ok: true }`
   152→
   153→### Trust & safety
   154→- `GET /api/me/blocks` → `{ blocks: PublicPerson[] }`; `POST /api/me/blocks` `{ username }`; `DELETE /api/me/blocks?username=` → `{ ok: true }`
   155→- `POST /api/reports` `{ targetType: PROJECT|PROFILE, targetId, reason, details? }` → `{ ok: true }`
   156→- `GET /api/me/privacy` → `{ profileVisibility, aiConsent }`
   157→- `PATCH /api/me/privacy` `{ profileVisibility?, aiConsent? }` → `{ profileVisibility, aiConsent }` (audit-logged)
   158→- `POST /api/me/export` → `{ job: { id, status } }` (creates ExportJob, synchronously fills payload JSON of user's own data)
   159→- `GET /api/me/export/:jobId` → `{ job }`; when READY, `payload` contains full data export JSON (owner only)
   160→- `POST /api/me/deletion` `{ reason? }` → creates DeletionRequest + immediately soft-deletes account (anonymize email/name, `deletedAt=now`, revoke sessions) → `{ ok: true }`
   161→- `GET /api/me/audit` → `{ events: [{ action, targetType, targetId, createdAt }] }`

   163→### Insights (owner-only, labelled "estimated")
   164→- `GET /api/me/insights/overview` → `{ totals: { profileViews, projectViews, saves, followers }, series14d: [{ day, views }], topProjects: [{ id, title, views, saves }] }`
   165→- `GET /api/me/insights/projects` → `{ projects: [{ id, title, views, saves, views14d }] }`

   167→### BEAN Intelligence (AI)
   168→- `GET /api/ai/capabilities` → `{ available: boolean, features: [{ id, label, description }], dailyLimit: number, usedToday: number, consentRequired: boolean }`
   169→- All AI features require: auth + `aiConsent=true` (else 403 `{ error: 'AI is not enabled for your account. Enable it in Settings.' }`) + usage limit (default 30/day) + rate limit.
   170→- `POST /api/ai/improve` `{ field: 'description'|'summary'|'bio'|'process'|'outcome', content, projectContext? }` → `{ text }` (LLM rewrite; never auto-saves)
   171→- `POST /api/ai/suggest` `{ projectId? , title?, description? }` → `{ summary?, skills?: string[], category?: string }` (JSON-validated LLM output)
   172→- `POST /api/ai/chat` `{ conversationId?, message }` → `{ conversationId, reply }`. Context: ONLY the user's own profile + projects they own (never other users' private data). Persist AiConversation/AiMessage.
   173→- `GET /api/ai/conversations` → `{ conversations: [{ id, title, updatedAt }] }`
   174→- `GET /api/ai/conversations/:id` → `{ conversation: { id, title, messages: [{ role, content, createdAt }] } }` (owner only)
   175→- LLM calls: `aiComplete(system, messages)` in `@/lib/ai` (z-ai-web-dev-sdk, thinking disabled, timeout 60s, returns `{ text }` or throws with safe message). Log every call to AiUsage.
