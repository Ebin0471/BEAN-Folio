    43→
    44→### Next.js 16 specifics
    45→- Route handler dynamic params are Promises: `export async function GET(req: NextRequest, { params }: { params: Promise<{ id: string }> })` → `const { id } = await params`
    46→- `cookies()` from `next/headers` is async: `const store = await cookies()`
    47→- Use `NextRequest`/`NextResponse` from `next/server`
    48→- All API routes under `src/app/api/**/route.ts` (API routes are allowed; PAGE routes other than `/` are NOT)
    49→
    50→### Server helpers (already implemented by orchestrator — import, do not re-create)
    51→```ts
    52→import { db } from '@/lib/db'                    // Prisma client
    53→import { getSessionUser } from '@/lib/auth'      // → User | null (validates session cookie)
    54→import { setSessionCookie, clearSessionCookie } from '@/lib/auth'
    55→import { ok, err, parseBody, getClientKey, rateLimit } from '@/lib/api-helpers'
    56→import { saveUpload } from '@/lib/media'         // validates magic bytes, writes to uploads/
    57→import { aiComplete, aiCapabilities } from '@/lib/ai'
    58→```
    59→- `ok(data, status=200)` → NextResponse.json(data)
    60→- `err(message, status=400, code?)` → NextResponse.json({ error, code? }, { status })
    61→- `parseBody(req, zodSchema)` → `{ data } | { response }` — check `if ('response' in r) return r.response`
    62→- `rateLimit(key, limit, windowMs)` → boolean (in-memory)
    63→- Hash passwords with `hashPassword` / `verifyPassword` from `@/lib/auth` (scrypt, never store plaintext)
    64→
    65→### Error shape (all endpoints)
    66→- 400 validation `{ error: string }`, 401 `{ error: 'Authentication required' }`,
    67→  403 `{ error: 'Not allowed' }`, 404 `{ error: 'Not found' }`, 429 `{ error: 'Too many requests' }`, 500 `{ error: 'Something went wrong' }`
    68→- NEVER leak stack traces, internal errors, or secrets. Wrap handlers in try/catch → err('Something went wrong', 500)

    93→## API CONTRACT v1 (authoritative)
    94→
    95→All endpoints under `/api`. JSON bodies. Cookie session auth (`bean_session`).
    96→
    97→### Auth
    98→- `POST /api/auth/register` `{ email, password (min 8), name }` → 200 `{ user: PublicMe }` + sets cookie. 409 if email taken.
    99→- `POST /api/auth/login` `{ email, password }` → 200 `{ user: PublicMe }`. 401 invalid credentials.
   100→- `POST /api/auth/logout` → 200 `{ ok: true }`, clears cookie.
   101→- `GET /api/auth/me` → 200 `{ user: PublicMe | null }`.
   102→  - `PublicMe = { id, email, name, username, headline, bio, location, avatarUrl, coverUrl, availability, contactEmail, websiteUrl, professions: string[] (slugs), skills: string[] (slugs), aiConsent, onboarded, profileVisibility, isDemo, createdAt }`
   103→
   104→### Onboarding & profile
   105→- `POST /api/me/onboarding` `{ username, displayName, professions: string[], skills?: string[], bio?, location?, headline? }` → 200 `{ user: PublicMe }`. Validates username `[a-z0-9-]{3,24}` unique. Sets `onboarded=true`.
   106→- `GET /api/me/profile` → `{ user: PublicMe, stats: { projects, published, followers, following, profileViews } }`
   107→- `PATCH /api/me/profile` (partial: `name, headline, bio, location, availability, contactEmail, websiteUrl, avatarMediaId, coverMediaId, professions, skills, profileVisibility`) → `{ user: PublicMe }`
   108→- `GET /api/profiles/:username` → public profile `{ profile: { id, name, username, headline, bio, location, avatarUrl, coverUrl, availability, websiteUrl, professions, skills, createdAt, stats: { followers, following, projects, profileViews? } }, isFollowing: boolean, projects: ProjectCard[] (public+published only; include UNLISTED if owner), collections: [{id,name,description,items:ProjectCard[]}] }`. Records a ProfileView (deduped/day).
   109→- `GET /api/professions` → `{ professions: [{ slug, label, group }] }` (curated static list served from DB seed or code constant)
   110→- `GET /api/skills` → `{ skills: [{ slug, label }] }`
   111→
   112→### Media
   113→- `POST /api/media/upload` multipart form: `file` (+ optional `kind`). → 200 `{ media: { id, kind, mime, size, url } }`. Auth required. Limits: images ≤ 8MB (jpeg/png/webp/gif), video ≤ 64MB (mp4/webm/quicktime), audio ≤ 20MB, docs(pdf) ≤ 10MB. Magic-byte validation.
   114→- `GET /api/media/:id/raw` → binary stream with content-type + cache-control. Public if linked to published content or owned; simplest correct rule: any READY media is servable (IDs are unguessable cuids) — but PRIVATE-project media must 403 unless owner: check `ProjectMedia→Project.visibility` and avatar/cover ownership.
   115→- `GET /api/media/:id` → `{ media }` metadata (owner only). `DELETE` → owner only, removes file + row.
   116→
   117→### Projects
   118→- `POST /api/projects` `{ title, summary?, description?, category?, visibility?, coverMediaId?, brief?, process?, challenges?, outcome?, role?, externalUrl?, repoUrl?, skills?: string[], tools?: string[], media?: [{ mediaId, caption? }], contributors?: [{ name, role?, contribution? }] }` → `{ project: FullProject }` (status DRAFT).
   119→- `GET /api/projects?status=DRAFT|PUBLISHED` → `{ projects: ProjectCard[] }` (OWN projects only, all visibilities).
   120→- `GET /api/projects/:id` → `{ project: FullProject, owner: PublicPerson, isOwner, isSaved, canEdit }`.
   121→  - PRIVATE → 404 unless owner. UNLISTED → readable by direct link. Records ProjectView (deduped per viewer/day) when PUBLISHED and not owner.
   122→- `PATCH /api/projects/:id` (same fields as POST, partial; owner only) → `{ project }`
   123→- `DELETE /api/projects/:id` → `{ ok: true }` (owner only)
   124→- `POST /api/projects/:id/publish` → `{ project }` (requires title + cover OR ≥1 media; sets status PUBLISHED, publishedAt). Also `POST /api/projects/:id/unpublish` → back to DRAFT.
   125→- `FullProject = ProjectCard fields + description, brief, process, challenges, outcome, role, externalUrl, repoUrl, skills: string[], tools: string[], media: [{ id, mediaId, url, kind, caption, order }], contributors: [{ id, name, role, contribution }], counts, visibility, status, publishedAt, createdAt, updatedAt`
   126→- `ProjectCard = { id, title, summary, category, coverUrl, visibility, status, publishedAt, updatedAt, owner: { username, name, avatarUrl }, counts: { views, saves }, skills: string[] }`
   127→- `POST /api/projects/:id/view` → records view (used by client on mount for anon tracking), 200 `{ ok: true }`

   129→### Discover & search
   130→- `GET /api/discover?cursor=&limit=12&category=` → `{ items: [{ project: ProjectCard, reason?: string }], nextCursor }`. Ranking: published+PUBLIC only, recency-weighted engagement (saves+views), same-profession boost for signed-in viewer, new-creator boost (first project), never follower-count-only. `reason` examples: "New on BEAN Folio", "Matches your profession: Film", "Popular in Architecture".
   131→- `GET /api/search/projects?q=&category=&skill=&sort=recent|saved&cursor=` → `{ items: ProjectCard[], nextCursor }` (PUBLIC+PUBLISHED only)
   132→- `GET /api/search/profiles?q=&profession=&skill=&cursor=` → `{ items: PublicPerson[], nextCursor }` (PUBLIC profiles only)
   133→  - `PublicPerson = { username, name, headline, avatarUrl, location, professions, skills, stats: { followers, projects } }`

   138→- `GET /api/me/collections` → `{ collections: [{ id, name, description, isPublic, items: ProjectCard[] }] }`
   139→- `POST /api/me/collections` `{ name, description?, isPublic? }` → `{ collection }`

   149→- `GET /api/me/inquiries` → `{ incoming: InquiryDTO[], outgoing: InquiryDTO[] }` (`InquiryDTO = { id, type, subject, message, status, createdAt, project?: { id, title }, counterparty: PublicPerson }`)

   151→- `GET /api/me/notifications` → `{ notifications: [{ id, type, payload (parsed object: e.g. { actor, projectTitle }), readAt, createdAt }], unreadCount }`

   157→- `GET /api/me/privacy` → `{ profileVisibility, aiConsent }`
   158→- `PATCH /api/me/privacy` `{ profileVisibility?, aiConsent? }` → `{ profileVisibility, aiConsent }` (audit-logged)
